# DocuSign CLM filepart processing

Set `CLM_URL`, `CLM_USERNAME`, `CLM_PASSWORD`, and `CLM_ZONES` in the environment. Set `CLM_ZONES` to exactly one folder name directly under `CLIENTS/SPAIN`, for example `Zona Sur`. Use separate installations and data directories for separate zones. Do not commit credentials. Start the app with `docker compose up --build` or `streamlit run app.py`.

The processing button searches each configured zone for `filepart`, uploads each download unchanged as a new version, traverses all search pages, waits ten minutes, closes the browser, signs in using a fresh browser session, and repeats the filtered search until a clean search is empty. It then uploads a total ledger and closes the browser. The history records document IDs, names, zones and timestamps. If a clean search returns only previously processed or exhausted documents, the app does not upload them again and proceeds to the total ledger. After submission, the app waits up to 45 seconds for the DocuSign check-in confirmation. If it does not appear, the app records the outcome as unconfirmed in the total ledger without resubmitting.

Successful downloads are retained for four hours after confirmation. The app checks for expired files once per minute while running and on startup. If it is stopped at the deadline, deletion happens after it restarts. Docker stores downloads, pending records and history in the `clm-data` volume. Preserve that volume across restarts. `CLM_DATA_DIR` changes the storage directory outside Docker.

After processing each nonempty result page, the app creates `REPORT <ZONE> <NUMBER> <HH:MM>.csv` (using the last processed document time in Spain) and uploads it from a separate tab to `Users / Internal / Registro correcciones filepart`. The search tab stays on the results page until the report is confirmed, then advances. Reports contain the zone, filename, DocuSign path, document URL, document ID and processing time. Local journals and report files are kept in `CLM_DATA_DIR` to protect against interrupted processing; if a page or upload is unfinished, processing stops for reconciliation rather than silently repeating an upload.

When a fresh search is empty, the app creates `<ZONE> - TOTAL LEDGER.csv` from all recorded history for that zone and uploads it to the same destination. An existing local or remote total ledger, unfinished page journal, or pending upload requires reconciliation before retrying. Browser processing ends after the total ledger upload; the app and its periodic cleanup worker remain running.

A document that fails before an upload is submitted is retried on fresh passes, up to four total attempts. After the fourth failure it is listed in the total ledger as not processed, with its attempt count and reason. An unconfirmed submission is recorded for reconciliation; an interruption during submission still stops for reconciliation. Attempt records persist in `CLM_DATA_DIR`.

The main interface starts without opening DocuSign. Select **Run setup** to sign in, then use the processing button for the configured zone. The document table updates from processing events and the separate ledger list updates after each confirmed report upload. The ten-minute wait, retries and stops are displayed as status messages. `demo.py` remains a separate sample-only interface. Processing results in the interface are held in the browser session; durable processing history, attempts and reports remain in `CLM_DATA_DIR`.
